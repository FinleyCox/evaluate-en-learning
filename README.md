# 生徒ケアAIトレーナー PoC

イーオン様向け「講師が生徒対応を練習するAIトレーナー」の試作。
2026年11月5日の打ち合わせで論点になった **「評価が実務で成立するか」** を、実際に動かして確かめるための最小構成です。

- Step1 … 講師が生徒役AIと会話して練習する
- Step2 … 評価AIが評価軸にそって5段階で採点し、根拠の発話を引用する
- Step3 … 同じログをトレーナーが独立に採点し、**重み付きκ**で一致度を測る
- その上に、講師が自分の上達を追える「上達」画面を載せている

材料: Notion「PoCの進め方」議事録 / 提案スライド「生徒ケアAIトレーナーPoC 評価軸とスケジュール（案）」/ 貴社資料「ペルソナと場面 Personal Trainer PoC」

## 起動

```bash
npm install
cp .env.example .env     # ANTHROPIC_API_KEY を書く
npm start                # http://localhost:5173
```

`ANTHROPIC_API_KEY` を設定しなければ **MOCKモード**で起動し、台本の生徒役と自動計測だけの採点で画面を通しで触れます（デモ用）。

```bash
npm run check            # 自動計測・κ・判定レポート・上達集計・直列化の検証（API不要）
npm run check:voice      # 音声モードと、音声が使えないブラウザでの挙動を通しで検証（API不要／Chromeが要る）
npm run lint             # ESLint
npm run seed             # 「上達」画面を触るためのデモデータを14件入れる（API不要）
```

デモデータは `data/sessions/*-seed*.json` を消せば消えます。

## 画面

| タブ | できること |
| --- | --- |
| 上達 | 講師ごとの上達。総合スコア・練習時間・連続練習日数・場面の制覇、週の練習のドットグリッド、評価軸5つの平均と伸び、総合スコアの推移、次に取り組む場面 |
| 1. 練習 | 6場面から選び、生徒役AIと英語で会話する。**打つ**か**声で話す**かを選べる。生徒は答えるまで5〜8秒黙り、その間に講師が口を開くと「割り込み」として記録される |
| 2. 評価・採点 | 左に会話ログ、右は「自動計測／評価AIの採点／講評／トレーナー採点」の切り替え。同じログを3回採点して安定性も測れる |
| 3. 判定レポート | 蓄積したセッションを、提案スライドp.4の判定基準に突き合わせる |
| 評価軸・ペルソナ | 採点に使っている定義そのもの（キックオフでの議論用） |

トレーナー採点は既定で **ブラインド**（登録するまでAIのスコアがぼかされる）。κを正しく測るためです。

どのタブも**ページ全体をスクロールせずに1画面で見られる**ようにしてあります。機能ごとに枠を分け、長い中身（会話ログ、採点の根拠、セッション一覧、評価軸の定義）だけがその枠の中でスクロールします。枠の端に薄い影が出ているときは、そこにまだ続きがあります。表示領域が狭い（幅1040px未満）か低い（高さ660px未満）ときは、無理に詰めずに縦に積む並びへ切り替わります。

## 声で話す練習

練習の開始時に「テキストで打つ／声で話す」を選べます。声を選ぶと、ブラウザのマイクと読み上げを使って、講師は手を使わずに会話します。

- **話し終わって1.5秒黙ると、そのまま送信される**。送信ボタンを押す動作が会話に挟まらない
- **生徒役の返事は読み上げる**。読み上げている間は、自分の声を拾わないようマイクを止める
- **生徒が黙って考えている間もマイクは開いている**。ここで講師が口を開いた時刻が「割り込み」になる
- 聞き取った文は送信欄に出るので、打ち直してから送ることもできる

**声で練習すると、評価の材料が1つ実測に変わります。**

| | 打って練習 | 声で練習 |
| --- | --- | --- |
| 講師の1回の連続発話の秒数 | 文字数からの推定（150wpm 換算） | **実測**（話し始め〜声の切れ目） |
| 割り込みの時刻 | 送信ボタンを押した時刻 | **話し始めた時刻** |

この2つは評価軸「生徒が主役の会話配分」「考える時間の確保」の採点の手がかりそのものです。打って練習した回は、講師が実際に話すより速く読み書きできるぶん、秒数が短めに出ます。どちらで測った値かは、画面の自動計測（「音声の実測／文字数からの推定」）にも評価AIへ渡す要約にも必ず添えます。混在した会話は、回ごとに実測と推定を使い分けます。

マイクと聞き取りはブラウザ標準（Web Speech API）を使うため、**Chrome か Edge が要ります**。対応していないブラウザでは「声で話す」を選べず、テキストで練習します。生徒が話している間はマイクを止めているので、**読み上げへの被せ（生徒の発話中の割り込み）は測りません**。測るのは沈黙中の割り込みだけです。

## 実装している評価軸（提案スライド p.2）

| 軸 | 見る行動 | 対象の場面 | 採点の手がかり |
| --- | --- | --- | --- |
| 生徒の状態への気づき | 疲れや不調の一言を受け止め、本題へ移る | ロビー1・3 | 受け止めの応答が1往復以上あるか |
| 話の掘り下げと記憶 | 前回の話題に自分から触れ、質問で話を広げる | ロビー2 | 前回の話題に触れたか／単語だけの相づちが続いたか |
| 生徒が主役の会話配分 | 自分の話は短く切り上げ、知らない話題は生徒に聞く | ロビー4 | 講師の発話量比率・連続発話秒数（**自動計測**。声で練習した回は実測） |
| 考える時間の確保 | 答えを急かさず3〜5秒待つ | 生徒ケア1 | 沈黙を破るまでの秒数（**自動計測**） |
| 自力で言えるよう支援 | すぐ訳さず、説明や言い換えを促す | 生徒ケア3 | 即答した回数とヒントで引き出した回数 |

各軸に5段階の記述子（`config/rubric.json`）を置き、評価AIは印象ではなく記述子で採点します。
今回の場面に対応しない軸は `applicable: false` として κ の対象から外れます。

## 「上達」画面について

講師の練習が続かなければ評価の精度を測るデータも貯まらないので、**練習した人が自分の伸びを見られる画面**を入れています。

- **週の練習** … 過去5週間を7列のドットグリッドで出す。丸が濃いほどその日の練習回数が多く、今日は赤いリングで示す
- **評価軸の上達** … 5軸それぞれの平均点（5点満点）と、練習回数の前半と後半の平均差（伸び）
- **総合スコアの推移** … 1回の練習で採点対象になった軸の平均を、古い回から並べた折れ線
- **次に取り組むこと** … 未練習の場面があればそれ、なければ平均が最も低い軸の場面を出し、その場面の練習へ飛ぶ

配色は**英会話イーオンのコーポレートサイト（aeonet.co.jp）から実際に取った値**です。ブランド青 `#007cbf`（選択中のタブ・見出しの罫・グラフ）、ネイビー `#064562`、CTAの赤 `#c94d4a`（主ボタン・今日・連続日数）、本文 `#2d2d2d`、面 `#ffffff` / `#f5f8fa`、書体は Noto Sans JP。白いヘッダー帯に細い罫、見出しの頭にブランド色の縦罫、ボタンはピル、という作りも同サイトに合わせています。
画面の並び（サマリ帯・ドットグリッド・数値タイル）は Bogdan Nikitin / Nixtio「Language Learning AI App」（Dribbble）を参考にしています。
データに使う色（練習量の3段ランプ）は、色相が1つであること・明度が単調に変わること・段差が十分あること・いちばん明るい段が面に対して2:1以上あることを検証スクリプトで確かめ、ライト／ダーク両方 PASS です。グラフはいずれも1系列なので凡例は置かず、値を直接ラベルし、ドットグリッドと評価軸バーには表での表示も付けています。

## 作りのうえで気をつけている点

- **.env の読み込みは Node 標準の `process.loadEnvFile`** に任せている。シェルで指定した環境変数のほうが優先される
- **セッションごとに処理を直列化している**（`server/lock.mjs`）。ターンの追加や採点は「読み込む → 変える → 書き出す」で途中に待ちが入るため、要求が重なると後から書いた側が前の変更を消す。同じセッションへの要求は前のものが終わるまで待たせ、画面側も送信中は次を受け付けない
- **セッションの保存は一時ファイル経由**。書き込み中に落ちても壊れたJSONが残らない。万一壊れたファイルがあっても、そのセッションだけ飛ばして残りは読む
- **MOCKモードの応答（即時）は「応答時間 平均2.0秒以内」の母数に入れない**。APIキーなしで判定基準が誤って達成になるのを避けるため
- **評価の段階数は `config/rubric.json` の `scale`** を見る。画面もκの計算も同じ値を使う
- **文字は縦横の比を変えずに拡大する**。推移グラフのSVGは比を保ったまま伸ばす（比を崩すと中の数字が横に潰れる）

## 構成

```
config/      評価軸・ペルソナ・場面・判定基準（すべてJSON。キックオフの議論結果はここを直せば反映される）
server/
  student.mjs    生徒役AI（ペルソナ＋場面をシステムプロンプトに展開）
  evaluator.mjs  評価AI（構造化出力で軸別スコア＋引用を必ず返させる）
  metrics.mjs    自動計測（発話量比率・連続発話秒数・沈黙を破るまでの秒数・応答時間）
                 連続発話の秒数は、声で練習した回は実測値、打った回は文字数からの推定
  agreement.mjs  重み付きκ（二次重み）と一致の内訳
  report.mjs     判定基準との突き合わせ
  progress.mjs   講師ごとの上達集計（連続日数・週グリッド・軸別の伸び）
  lock.mjs       セッション単位の直列化
  store.mjs      セッションの保存と読み出し
public/      画面（依存ライブラリなし。音声モードも Web Speech API だけで動く）
scripts/
  selfcheck.mjs         自動計測・κ・判定レポート・上達集計・直列化の検証
  voicecheck.mjs                   音声まわりの通し検証（本物の画面を実際のChromeで動かす）
  voicecheck.stub.browser.js       その中で画面に差し込む、にせマイク・にせ読み上げ
  voicecheck.voice.browser.js      声で練習するシナリオ
  voicecheck.fallback.browser.js   音声が使えないブラウザとテキスト練習のシナリオ
  seed.mjs              「上達」画面用のデモデータ
```

モデルは評価AIが `claude-opus-5-5`（effort: high）、生徒役は既定で同じモデル（effort: low）。
生徒役の応答時間が判定基準（平均2.0秒以内）に届かない場合は、`.env` の `STUDENT_MODEL_ID` で速いモデルに差し替えます。

## このPoCで測れること / 測れないこと

測れる（提案スライド p.4 の判定基準に対応）:

- 採点の一致（重み付きκ） … AIとトレーナーの軸別スコアから自動計算。軸ごとの内訳とAIの甘辛（bias）も出る
- 採点の安定性 … 同じログを3回採点し、軸ごとの最大差を見る
- 応答時間 … 生徒役の生成時間をログから計測
- ペルソナの再現度 / 場面の成立 / 有用性 / 納得度 … トレーナーが会話ごとに入力

**測れない（本PoCの範囲外）:**

- 日本語訛りの英語音声の再現。読み上げも聞き取りもブラウザ標準（Web Speech API）で、音声そのものの品質はこのPoCの検証対象ではない
  （ElevenLabs IVC / Qwen3-TTS / Anam の比較は別資料「日本人英語の音声AI PoC」の担当）。
  ここで音声を使うのは、**間合いと発話量を実測するため**であって、音声AIの比較のためではない
- 聞き取りの精度そのもの。聞き間違いは送信欄に出るので講師が直せるが、精度の評価はしていない
- アバター表示（Anam連携）
- 複数の生徒への同時対応（貴社資料で「不可」と合意された 生徒ケア2・4）

## キックオフで決めたいこと

1. `config/rubric.json` の5軸と記述子で過不足がないか（教務部・トレーナー）
2. `config/persona.json` の「前回の話題」「当日の状態」（弊社補完の2項目）を確定できるか
3. 自動計測のしきい値（待ち時間3〜5秒、講師の発話量比率）をトレーナーの採点と照らしてどこに置くか
4. 試用する講師とトレーナー5〜6組の人選と日程
5. 「上達」画面に何を出せば講師が練習を続けるか（連続日数・バッジ・ランキングなど、どこまで入れるか）
6. 試用を**声で話す**ほうに寄せるか。間合いと発話量を実測できる反面、Chrome が要り、聞き取りの誤りが会話に混じる
